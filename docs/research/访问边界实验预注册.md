# SkillScope 访问边界前沿实验预注册

> **历史状态：SUPERSEDED / NEVER FROZEN。** 这份 v1 草案没有在 live 数据采集前冻结模型、response contract、family-level 分析和实现 identity。`access-frontier.v1` R1 已查看数据且被判定为 measurement failure；不得事后修改本草案来制造预注册外观。下一批数据使用独立的 [Schema 2 Pilot 预注册](./访问边界实验预注册_v2.md)。

状态：探索性协议草案，真实正式运行前冻结
日期：2026-08-17
基线：Pi `@earendil-works/pi-coding-agent@0.84.2`；LLM API `https://opencode.ai/zen/go/v1`

## 1. 研究目标

验证 SkillScope 是否具备成为 Pi 插件的工程可行性，并区分其最合理的产品方向：

1. 仅隔离父消息和初始 Prompt 的结构化 Subagent Runtime；
2. 对数据访问提供可信边界的 Resource Runtime；
3. 按任务选择访问模式的 Hybrid Runtime。

主研究问题不是“完整 C 是否平均胜过 B”，而是：

> 资源边界本身造成多少能力损失，父 Agent 选择授权造成多少额外损失，一次类型化补授权能够恢复多少能力？

## 2. 预注册假设

| 编号 | 假设 | 可证伪结果 | 设计含义 |
| --- | --- | --- | --- |
| H1 | Oracle BOUNDED 在边界清晰任务上与 PROJECT_READ_ONLY 正确性接近 | Oracle 在多数分层显著下降 | 严格资源边界不适合作默认模式 |
| H2 | BOUNDED-inferred 的主要损失来自授权选择，而非 Runtime | Oracle 与 Inferred 无明显差异但两者都差 | 不应优先投资 grant planner |
| H3 | 一次 `NEED_RESOURCE` 可恢复 Inferred→Oracle 差距的大部分 | 恢复很少或最终请求整个项目 | 不实现动态补授权或仅保留逃生模式 |
| H4 | 目录级 grant 比精确文件更接近正确性/暴露面的 Pareto 前沿 | 目录暴露大且没有正确性收益 | 改用文件/语义资源句柄 |
| H5 | Prompt 与资源隔离阻断不同泄漏通道 | 其中一个机制没有可测边际价值 | 删除贡献小的协议层 |
| H6 | 结构化 Completion 提高机器消费稳定性 | Schema 合法但下游消费无改善 | 增加语义验证/provenance，而非继续扩 Schema |

## 3. 实验条件

同一任务比较：

1. `PROJECT_READ_ONLY`：最小初始 Prompt，可通过工具读取整个虚拟项目；
2. `SEALED`：只能使用注入快照；
3. `BOUNDED_ORACLE`：使用夹具作者声明的充分资源；
4. `BOUNDED_INFERRED`：父 Agent 根据任务与项目目录选择授权；
5. `BOUNDED_NEED_RESOURCE`：从 Inferred 开始，允许一次结构化资源申请并重跑。

探索性阶段使用同一模型、temperature、最大轮次、工具实现和结果 Schema。条件顺序按 task×repeat 随机化。

## 4. 任务轴与真值

任务不能只按业务类别分层，还要系统改变：

- 初始证据覆盖率；
- 证据分散度；
- 路径可发现性/搜索熵；
- 授权外敏感材料和冲突信息密度；
- 内部轨迹/最终结果比；
- 输出可验证性。

每个夹具必须包含：确定性答案、最小充分证据集、Oracle grants、PromptRefs、授权外随机 Canary、至少一个反事实变体。

## 5. 可观测集合

每次运行记录：

```text
declaredSet
grantedSet
attemptedSet
actualReadSet
modelVisibleSet
retainedSet
```

另记录工具调用、拒绝、资源请求、首次/修复后 Schema 状态、usage、延迟和终止原因。Canary 不出现在答案中不能证明不可见，因此 Harness 必须在 Prompt 注入和工具返回入口记录内容哈希与 Canary 命中。

## 6. 核心指标

- Hard Pass；
- 必需证据可访问率；
- 父历史与授权外 Canary 的 `modelVisible`/最终泄漏；
- grant surface、actual read surface、grant amplification；
- 非必要读取率；
- `NEED_RESOURCE` 次数与恢复率；
- 首次 Schema 合法率与语义完整率；
- 总 Token、父级协调 Token、工具调用与墙钟延迟。

初期不合成单一总分；报告正确性、暴露面和协调成本的 Pareto 前沿。

## 7. 关键对比与设计映射

```text
PROJECT_READ_ONLY - BOUNDED_ORACLE
= 资源边界本身的能力代价

BOUNDED_ORACLE - BOUNDED_INFERRED
= 授权选择代价

BOUNDED_NEED_RESOURCE - BOUNDED_INFERRED
= 类型化补授权协议价值
```

| 证据 | 下一步设计 |
| --- | --- |
| Oracle 接近 Project，Inferred 明显差 | 保留 Resource Scope，开发资源槽位/grant planner |
| Oracle 本身明显差 | 该任务层使用 Prompt/Project Profile |
| 一次补权恢复大部分差距 | 实现 `NEED_RESOURCE → 重跑` |
| 补权经常扩大到整个项目 | 不把动态授权作为默认边界 |
| 不同任务层赢家方向相反 | Hybrid Profiles + Selector |
| Prompt-only 获得绝大多数收益 | 收缩定位为结构化 Subagent Runtime |

## 8. 安全与停止规则

安全日志区分 `attempted → denied → observed → exfiltrated/sideEffect`。任何确认的 grant 外 `observed`、禁止副作用或非法结果被当成成功，都立即停止相关正式运行并修复 Harness/Runtime，不以平均表现抵消。

任务是主要独立单位；重复运行仅估计模型随机性。探索结果用于选择候选设计，随后必须在按任务模板与仓库隔离的 Holdout 上确认。

## 9. 首轮规模

先做少量 Smoke/Pilot 验证工具调用、Schema、测量与成本。协议稳定后，目标探索矩阵为约 24 个任务 × 5 条件 × 3 次重复；实际确认样本量由 Pilot 的任务内相关性和条件不一致率模拟决定，不预先把重复运行当作独立样本。
