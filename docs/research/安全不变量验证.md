# SkillScope 安全不变量验证

状态：v0.1 工具边界已执行；稳定 symlink 逃逸已验证，并发 TOCTOU 不在当前保证内
日期：2026-08-18
范围：本地确定性 hostile tests；不调用 LLM，不读取或打印密钥

## 1. 验证目标

本轮将“Resource Gateway 能够约束模型通过 `scope_read` / `scope_list` / `scope_search` 观测的资源”拆为可执行的硬不变量。攻击者是可以构造任意工具参数的子 Agent；被保护对象是未授权的项目资源、Canary 和带外 Trace。

这些测试不用平均分数。任一未授权资源进入 `actualRead` 或 `modelVisible`，都是安全门禁失败，必须在真实模型实验前修复。

## 2. 威胁模型与不作出的承诺

### 2.1 本轮承诺

- 所有资源路径在一个统一网关入口规范化和授权；
- `SEALED` 不允许运行期探索；
- `BOUNDED` 只允许 grant 的路径、后代和操作；
- `PROJECT` 可读虚拟项目目录，但仍拒绝非法路径；
- 被拒绝的尝试可审计，但其内容不进入模型可见集合；
- Trace 位于所有子 Scope 授权根之外。

### 2.2 明确不承诺

Resource Gateway 是工具层的能力边界，不是 OS 安全沙箱。当前 in-process Pi Extension 和其他 JavaScript 代码继承 Pi 进程的用户权限，可以绕过工具网关直接读文件、环境变量、网络或进程内存。因此本轮结果不能推导出：

- 防恶意 Skill/Extension 作者；
- 主机文件系统、凭据、网络或进程级隔离；
- 对并发恶意主机写者的实体文件系统 TOCTOU/完整 symlink 安全证明（稳定越界 symlink 已单独验证）。

威胁模型一旦包含恶意代码，就需要 ChildProcess/Container 后端、裁剪后的环境变量和 OS 级文件/网络策略；不能用更多 Prompt 或 Gateway 单测代替。

## 3. 安全不变量

| 编号 | 不变量 | 失败判定 |
| --- | --- | --- |
| S-01 | 网关只接受项目相对、以 `/` 分段的规范路径；目录操作的空值规范为虚拟根 `.` | 绝对路径、Windows drive/UNC、反斜杠、NUL 或任意 `..` 分段被执行 |
| S-02 | grant 包含是 segment-aware，不是字符串前缀 | grant `safe` 可读 `safe2/*`，或 grant `a.txt` 可读 `a.txt.bak` |
| S-03 | grant 的路径范围和 `read/list/search` 操作独立授权 | 仅 `read` grant 成功执行 `list` 或 `search` |
| S-04 | `SEALED` 对三类探索操作全部 fail-closed | 任一操作返回资源数据 |
| S-05 | `BOUNDED` 中 grant 外资源不可观测 | grant 外路径/内容/Canary 进入 `actualRead` 或 `modelVisible` |
| S-06 | `PROJECT` 扩大资源面但不放弃路径校验 | traversal/绝对路径在 `PROJECT` 成功 |
| S-07 | 审计集合保持单向性 | denied 尝试未记入 `attempted/denials`，或错误记入 `actualRead/modelVisible` |
| S-08 | Unicode 与编码表达不产生授权别名 | NFC grant 授权 NFD 变体，或 `%2e%2e`/全角分隔符被隐式解码为 traversal |
| S-09 | 带外 Trace 根不在项目内，也不能通过 symlink 别名落回项目 | Trace 直接或经 symlink 写入 cwd 后可被 Scope 读取 |
| S-10 | 虚拟 Resource Broker 没有 symlink/TOCTOU 状态；real-fs snapshot 拒绝稳定的越界 symlink | 虚拟记录发生链接解引，或稳定的越界 symlink 内容进入 snapshot |

## 4. Hostile 测试矩阵

| 类别 | 攻击样本 | 预期 | 状态 |
| --- | --- | --- | --- |
| Traversal | `../secret`, `a/../../secret`, `a/../b`, `..`, `./../x` | `INVALID_PATH` | PASS；含 7,168 条生成路径 |
| Absolute | `/etc/passwd`, `//server/share`, `C:\\secret`, `C:/secret`, `C:secret`, `\\\\server\\share` | `INVALID_PATH` | PASS |
| Separator/NUL | `safe\\file`, `safe\0file` | `INVALID_PATH` | PASS |
| Prefix collision | grant `safe/` 对 `safe2/canary.txt`；grant `a.txt` 对 `a.txt.bak` | `UNAUTHORIZED` | PASS；含 1,024 次生成操作 |
| Operation collision | read-only grant 执行 list/search；list-only grant 执行 read/search | `UNAUTHORIZED` | PASS |
| Mode | SEALED 三操作；PROJECT 的 traversal | SEALED 或 INVALID_PATH | PASS |
| Unicode | NFC/NFD 文件名、全角斜杠、Unicode dot | 精确 code-point 匹配，不产生别名 | PASS |
| Encoding | `%2e%2e/secret`；多字节内容的 byte limit | 不做 URL decode；不返回半个 UTF-8 code point；`bytes <= maxBytes` | PASS |
| Audit | 同时执行允许与拒绝请求 | attempted/denials 包含拒绝，actualRead/modelVisible 仅含成功 | PASS |
| Canary | 搜索 grant 外 Canary；在 hostile path 中放 Canary | 结果/modelVisible 不含 grant 外 Canary；审计 JSON 无明文 | PASS |
| Trace lexical | traceRoot 等于/位于 cwd；cwd 内 `..traces` | 创建前拒绝 | PASS |
| Trace symlink | cwd 外 traceRoot symlink 指回 cwd；已存 scope dir symlink 逃逸 | 创建前拒绝，不留下目录副作用 | PASS |
| Trace reachability | 猜测绝对路径和 `../` 读 Trace | 网关拒绝，Trace 不进 modelVisible | PASS |
| real-fs symlink | BOUNDED 显式文件/目录 symlink 越 cwd；PROJECT 遍历 symlink | 拒绝或跳过，外部内容不进 snapshot | PASS |
| Concurrent TOCTOU | `realpath/stat/readFile` 之间并发交换路径 | 不读取交换后的越界 inode | NOT PROVEN；当前威胁模型不包含并发恶意主机写者 |

## 5. 编码与文件系统边界决策

### 5.1 URL 编码

Resource Broker 接口接收的是虚拟资源路径，不是 URL，因此不做 percent-decoding。`%2e%2e` 只是字面文件名，不等于 `..`。如果未来 HTTP/URI adapter 需要解码，必须在 adapter 边界解码一次后重新跑完整路径校验，并拒绝二次解码语义。

### 5.2 Unicode

当前虚拟文件表使用 JavaScript 字符串的精确 code-point 语义，不自动做 NFC/NFD 归一化。这会使路径交互更严格，也避免 grant 在不同文件系统上意外扩张。实体 macOS 文件系统 adapter 不能直接沿用此结论，必须用目标文件系统的 `realpath`/inode 语义重测。

## 6. Symlink 与 TOCTOU 处理

实验 Harness 的 Resource Broker 是纯虚拟文件系统：资源是构造时拷贝的 `path + content` 记录，没有 symlink、inode、文件描述符或“校验后替换”状态。确定性测试还覆盖了 Pi real-fs snapshot adapter：显式 grant 的文件/目录 symlink 指向 cwd 外时拒绝，PROJECT 遍历时跳过 symlink，外部 Canary 没有进入 snapshot。

但当前 real-fs adapter 仍采用 `realpath -> stat -> readFile`。如果同一用户权限的恶意并发进程能在这些步骤间交换路径，JavaScript 层的重新检查无法给出无竞态证明。本轮不用概率性 race loop 伪装成确定证据，而是把该项标记为 `NOT PROVEN`。这与“工具网关不是 OS 沙箱”的边界一致。

未来 real-fs adapter 至少需要：

1. 对 grant root 和目标路径使用 `realpath`，做 segment-aware containment；
2. 避免“`realpath` 校验后再按原始路径打开”的 check/use 窗口；
3. 优先使用从受信根目录 fd 开始的 `openat` 类语义和 `O_NOFOLLOW`，并在打开后核对 inode/实际路径；
4. 对 list/search 递归遍历中每个目录项重复同等校验；
5. 使用一个可确定调度的竞态测试，在校验与打开之间把目标交换为 symlink，成功读取必须为 0。

## 7. 实施中发现并修复的问题

| 编号 | 发现 | 风险 | 修复与回归证据 |
| --- | --- | --- | --- |
| F-01 | TraceStore 最初只做 lexical `resolve/relative`，外部路径的 symlink 可指回 cwd | Trace 回写项目后可被 Scope 读取 | 对 cwd/traceRoot/scopeDir 做 canonical 检查；symlink root 和 scopeDir 攻击测试 PASS |
| F-02 | `mkdir(traceRoot)` 曾位于 canonical preflight 之前 | 拒绝前已在 cwd 留下目录副作用 | 从最近已存祖先计算 prospective canonical path；“拒绝且不创建”测试 PASS |
| F-03 | containment 使用 `startsWith("..")` | cwd 内合法名称 `..traces` 被错当项目外，形成 Trace 边界绕过 | 改为 `child === ".."` 或 `child.startsWith(".." + path.sep)` 的 segment-aware 判定；专用回归测试 PASS |
| F-04 | 虚拟路径曾允许 Windows drive-relative `C:secret` | 未来 Windows adapter 可能把它解释为驱动器当前目录 | 拒绝任意 `/^[A-Za-z]:/` 前缀；固定与生成路径测试 PASS |
| F-05 | UTF-8 曾按 byte 硬切后用 replacement char 解码 | `maxBytes=1` 可返回 3-byte `U+FFFD`，违反输出预算 | 回退到最后完整 code point；1–4 byte 边界测试 PASS |
| F-06 | 审计脱敏最初只处理 rawPath，canonical path/集合/事件可保留 Canary | 带外 Trace 的敏感内容残留 | snapshot/event 递归脱敏；hostile path 中的 Canary 明文为 0 |
| F-07 | real-fs adapter 一度混用 lexical cwd 和 canonical file path | macOS `/var -> /private/var` 下合法项目文件被误拒 | 预先冻结 canonical cwd 并全程使用；真实文件 snapshot 测试 PASS |

## 9. 结论限定

当前证据支持的结论是：在“不信任模型工具参数，但信任运行 SkillScope 的宿主代码，且不存在恶意并发主机写者”的威胁模型下，29 个确定性测试和 8,192 个生成攻击机会均未产生 grant 外观测。这些生成样本是相关的系统测试，不是 8,192 个独立随机实验，因此不用 `3/n` 将其换算为真实攻击失败率上界。

当前证据不支持“SkillScope 是安全沙箱”。恶意 Extension、直接 Node `fs`、环境变量、网络、进程内存以及并发文件系统交换仍需要 process/container/OS 能力边界。
